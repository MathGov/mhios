# MHIOS v0.8 Test Plan

## Implemented structural and behavioral checks

- JSON Schema validation and unique object identifiers.
- Required tier-divergence record.
- AI provenance, human review, self-authorization prohibition, and independent-first-pass control.
- Control owner and execution authority/shutdown/rollback assignment.
- Normative-mandate source, version, scope, effective interval, revocation, supersession, trust, hash, conflict, and review-state validation.
- Approved-execution binding to the exact configuration, current mandate snapshot, effective authorization interval, current evidence, active required controls, satisfied preconditions, and explicit empty-set dispositions.
- Decisiveness/framework-verdict consistency and selectable-set precondition for RLS.
- Material-unknown disposition guard.
- Unresolved concurrency conflict block at authority and execution stages.
- Stale gate-material evidence disposition.
- Generated-view source-version staleness.
- Graph-aware inference review for public redacted views.
- Institutional-precondition declaration for C2/C3 claims.
- Required Reality Grounding surface and consequence pathways.
- RG claim-authority role separation from option-rejecting gates.
- Canon audit-token namespace preservation.
- Constitutive-control resolution and owner checks for selectable `CSV_PASS_WITH_CONTROLS` options.
- Rights-emergency record, exact lexicographic orders, challenge, and return-to-normal checks without ordinary-selection serialization.
- Normative MUST-statement coverage reporting.
- Forty seeded mutation tests, including action-binding, execution-mandate currency, configuration binding, control, precondition, and execution-authorization mutations.

## Planned tests

- Complete state-transition matrix and reference integrity for every object link.
- Real event-log replay and merge-conflict resolution.
- Deeper jurisdictional-conflict, consent/delegation-chain, trust-store, privacy, and adversarial graph-redaction tests.
- Calculation replay using a working vertical slice.
- Security testing and accessibility studies with representative users.
- Anti-theater precision/recall against adversarial hollow runs.
- Burden, reviewer agreement, AI-off, and comparator studies.

## Boundary

The validator is intentionally bounded. It does not verify evidence truth, legal authority, moral correctness, institutional independence, domain safety, usability, construct validity, or empirical superiority.
